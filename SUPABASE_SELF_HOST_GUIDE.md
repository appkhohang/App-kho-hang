# Cẩm Nang Cấu Hình Capgo Self-Hosted Với Supabase (OTA Live Update)

Tài liệu này hướng dẫn chi tiết cách tự lưu trữ (Self-Hosted) hệ thống cập nhật Live-OTA cho ứng dụng Capacitor của bạn sử dụng **Supabase** (thay vì phụ thuộc vào tài khoản đám mây Capgo Cloud).

---

## 🌟 Tổng Quan Cơ Chế Hoạt Động
Khi bạn bật thuộc tính `localSupa` và `localSupaAnon` trong ứng dụng di động:
1. **Ứng dụng di động (Client)**: Sẽ gọi trực tiếp tới API REST của dự án Supabase để kiểm tra xem có bản cập nhật mới hay không (truy vấn bảng `channels` và `bundles`).
2. **Kho lưu trữ (Storage)**: Ứng dụng sẽ tải trực tiếp gói nâng cấp định dạng tệp ZIP từ một **Public Bucket** trên Supabase Storage.
3. **Đẩy bản cập nhật (CLI)**: Bạn sử dụng lệnh `npm run capgo-push:supabase` để tự động hóa việc tăng số hiệu phiên bản, biên dịch mã nguồn và tải gói cập nhật lên cơ sở dữ liệu & Storage của Supabase.

---

## 🛠️ BƯỚC 1: Cấu Hình Trên Supabase Dashboard

Hãy đăng nhập vào [Supabase](https://supabase.com/) và tạo một dự án mới (hoặc sử dụng dự án hiện có).

### 1. Tạo Database Tables (SQL Editor)
Vào mục **SQL Editor** trong thanh công cụ Supabase, tạo một Query mới và chạy đoạn mã SQL dưới đây để khởi tạo cơ sở dữ liệu phục vụ cho Capgo:

```sql
-- 1. Tạo bảng quản lý ứng dụng (apps)
CREATE TABLE IF NOT EXISTS public.apps (
    id text NOT NULL PRIMARY KEY, -- Thường là mã package như: com.xuongan.quanlykho
    name text NOT NULL,
    created_at timestamp with time zone DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- 2. Tạo bảng quản lý các phiên bản cập nhật (bundles)
CREATE TABLE IF NOT EXISTS public.bundles (
    id text NOT NULL, -- Số hiệu phiên bản (ví dụ: 1.0.72)
    app_id text NOT NULL REFERENCES public.apps(id) ON DELETE CASCADE,
    url text NOT NULL, -- Đường dẫn tải tệp ZIP từ Storage
    name text,
    status text DEFAULT 'active'::text,
    created_at timestamp with time zone DEFAULT timezone('utc'::text, now()) NOT NULL,
    PRIMARY KEY (id, app_id)
);

-- 3. Tạo bảng quản lý các kênh phân phối (channels)
CREATE TABLE IF NOT EXISTS public.channels (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name text NOT NULL, -- Ví dụ: production
    app_id text NOT NULL REFERENCES public.apps(id) ON DELETE CASCADE,
    version text NOT NULL, -- Phiên bản hoạt động trên kênh này (ví dụ: 1.0.72)
    created_at timestamp with time zone DEFAULT timezone('utc'::text, now()) NOT NULL,
    CONSTRAINT channels_app_id_name_key UNIQUE (app_id, name)
);

-- Bật quyền truy cập bảng công khai (Bypass RLS cho phép thiết bị đọc phiên bản mà không cần Login)
ALTER TABLE public.apps ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.bundles ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.channels ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Cho phép đọc công khai bảng apps" ON public.apps FOR SELECT USING (true);
CREATE POLICY "Cho phép đọc công khai bảng bundles" ON public.bundles FOR SELECT USING (true);
CREATE POLICY "Cho phép đọc công khai bảng channels" ON public.channels FOR SELECT USING (true);

-- Cho phép SERVICE ROLE (Capgo CLI dùng API Anon Key) ghi dữ liệu lên bảng
CREATE POLICY "Cho phép mọi thao tác cho API Key" ON public.apps ALL USING (true) WITH CHECK (true);
CREATE POLICY "Cho phép mọi thao tác cho API Key" ON public.bundles ALL USING (true) WITH CHECK (true);
CREATE POLICY "Cho phép mọi thao tác cho API Key" ON public.channels ALL USING (true) WITH CHECK (true);

-- 4. Tạo hàm kiểm tra tuân thủ 2FA (Yêu cầu bắt buộc bởi Capgo CLI v8+)
-- Do Capgo CLI mới khi đẩy bản cập nhật lên Supabase sẽ tự động gọi hàm RPC kiểm tra 2FA để đảm bảo tính bảo mật.
-- Trong mô hình tự lưu trữ (Self-hosted), chúng ta không cần từ chối truy cập do 2FA, do đó hàm này luôn trả về false.
CREATE OR REPLACE FUNCTION public.reject_access_due_to_2fa_for_app(app_id text)
RETURNS boolean AS $$
BEGIN
  RETURN false;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

-- Cấp quyền thực thi hàm cho các vai trò để Capgo CLI có thể gọi RPC kiểm tra
GRANT EXECUTE ON FUNCTION public.reject_access_due_to_2fa_for_app(text) TO public;
GRANT EXECUTE ON FUNCTION public.reject_access_due_to_2fa_for_app(text) TO anon;
GRANT EXECUTE ON FUNCTION public.reject_access_due_to_2fa_for_app(text) TO authenticated;
GRANT EXECUTE ON FUNCTION public.reject_access_due_to_2fa_for_app(text) TO service_role;
```

### 2. Cấu Hình Kho Lưu Trữ (Supabase Storage)
1. Vào mục **Storage** trên Supabase Dashboard.
2. Chọn **New bucket** để tạo một kho lưu trữ mới.
3. **QUAN TRỌNG:** Đặt tên bucket là **`bundles`** (viết thường hoàn toàn).
4. **BẬT** lựa chọn **`Public bucket`** (cho phép tải công khai không cần token đăng nhập).
5. Nhấn **Save** để lưu lại.

## 📱 BƯỚC 2: Cấu Hình Ứng Dụng Di Động (Client-Side)

Mở tệp `/capacitor.config.ts` của bạn và chuyển cấu hình sang sử dụng Supabase:

```typescript
import type { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  appId: 'com.xuongan.quanlykho',
  appName: 'Quan Ly Xuong An',
  webDir: 'dist',
  server: {
    androidScheme: 'https'
  },
  plugins: {
    CapacitorUpdater: {
      autoUpdate: true,
      
      // 1. Hãy tắt dòng cấu hình Capgo Cloud dưới đây (bằng cách comment lại //):
      // appId: '9bc744d0-6da2-4d42-9d7e-441b4c25b763'
      
      // 2. Mở comment và thiết lập thông tin Supabase tự lưu trữ của bạn:
      localSupa: 'https://your-project-id.supabase.co', // URL dự án Supabase của bạn
      localSupaAnon: 'your-public-anon-key'           // Anon Key lấy từ Project Settings -> API
    }
  }
};

export default config;
```

## 🚀 BƯỚC 3: Quy Trình Đẩy Phiên Bản Cập Nhật Mới (Push Live Update)

Hệ thống đã được tích hợp sẵn một script tự động hóa đa nền tảng thông minh tại `/scripts/push-supabase.js`.

### 1. Khai báo thông tin trong tệp `.env`
Mở tệp `.env` tại thư mục gốc dự án của bạn (hoặc tạo mới nếu chưa có) và bổ sung cấu hình sau:

```env
# URL dự án Supabase của bạn (lấy từ Project Settings -> API)
CAPGO_SUPABASE_URL=https://your-project-id.supabase.co

# MÃ SERVICE ROLE KEY (BẮT BUỘC để đẩy bản cập nhật)
# Lấy từ Project Settings -> API -> service_role (khóa bí mật bắt đầu bằng eyJ...)
# Chỉ khóa service_role mới có quyền ghi vào database và upload file ZIP lên Storage Bucket "bundles".
CAPGO_SUPABASE_SERVICE_KEY=your-supabase-service-role-key
```

> ⚠️ **LƯU Ý BẢO MẬT QUAN TRỌNG:**
> - **Client-side (Ứng dụng di động)**: Trong file `capacitor.config.ts`, bạn **vẫn giữ nguyên mã khóa `anon` công khai** để đảm bảo điện thoại của người dùng cuối chỉ có quyền đọc phiên bản mới (an toàn tuyệt đối).
> - **Upload script (Khi chạy build)**: Chỉ có script này chạy trên máy tính của bạn hoặc trên GitHub Actions mới được dùng mã khóa `service_role` để ghi đè/đẩy dữ liệu.

### 2. Tiến hành đẩy cập nhật bằng một câu lệnh
Mỗi khi bạn sửa đổi giao diện hoặc tính năng và muốn phân phối trực tiếp tới điện thoại của thợ, chỉ cần chạy lệnh sau trên Terminal:

```bash
npm run capgo-push:supabase
```

**Script này sẽ tự động chạy các bước:**
1. **Tự động tăng số hiệu phiên bản** Patch (ví dụ từ `1.0.71` lên `1.0.72`) đồng bộ trong cả `package.json`, `src/types.ts` và `public/version.json`.
2. **Biên dịch** toàn bộ mã nguồn của bạn ra thư mục `/dist` thông qua Vite.
3. **Đóng gói** và nén tệp tin `dist.zip`.
4. **Tải tệp tin ZIP lên Storage Bucket `bundles`** trong Supabase.
5. **Ghi nhận thông tin phiên bản mới** vào bảng `bundles` và cập nhật kênh `production` trong bảng `channels` để chỉ định điện thoại di động tự tải về.
